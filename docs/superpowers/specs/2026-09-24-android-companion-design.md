# VRCX 安卓伴侣：同一 Wi-Fi 查看电脑记录

状态：**设计待审核**。本设计针对现有仓库 `Kyoko412/VRCX-mirai` 的 Windows 版 VRCX 和一个新的 Android 客户端。

## 目标与边界

用户在手机和运行 VRCX 的电脑连接同一 Wi-Fi 时，通过安卓应用查看电脑已经保存的记录。电脑仍负责 VRChat 登录、采集和 SQLite 存储；手机只读取，不需要 VRChat 账号或密码。首版服务一台电脑上的一个当前登录账号；电脑关闭、断开 Wi-Fi 或切换账号时，手机清楚地显示不可用状态。

首版提供好友列表、单个好友的地图访问记录、共同好友见面次数与明细、简介变化历史，以及可明确归属当前账号的本人游戏日志。时间采用电脑保存的原始时间，手机按本地时区展示，并标明「VRCX 观察到」而非 VRChat 实际编辑或进出房间的精确时间。原有记录的观察盲区不会因为手机版而消失。

不包含远程互联网访问、云同步、离线副本、手机端 VRChat 登录、资料修改、好友操作或手机端继续采集。电脑上的现有 `VRCX.sqlite3` 是唯一数据来源。

## 仓库和交付方式

继续使用用户的 fork：`https://github.com/Kyoko412/VRCX-mirai`。开发分支为 `codex/android-companion`，从包含当前自定义功能的提交建立。电脑端、安卓端和接口契约放在同一仓库，使一次提交能表达两端兼容的改动。

- `Dotnet/MobileCompanion/`：Windows 端独立的本地网络服务、配对、认证和只读数据访问。
- `android/`：独立的 Android 应用工程，使用 Kotlin 与 Jetpack Compose。
- `docs/mobile-companion-api.md`：版本化的接口契约、字段含义、错误码和兼容规则。
- Windows 发布包继续包含电脑端程序；Android APK 作为单独构建产物发布在同一个仓库的 Releases。两者用明确的接口版本判断兼容性。

这不是把 Windows `.exe` 转成 APK，也不复用依赖桌面 `AppApi`、SQLite 全局对象和日志监听器的现有 Vue 页面。

## 电脑端服务与数据流

用户在 VRCX 设置里手动开启「手机查看」后，电脑端启动一个**独立**的只读 LAN 服务，显示当前局域网地址、连接状态、已配对设备和关闭入口。关闭开关、退出 VRCX 或切换登录账号时停止旧会话。现有 `127.0.0.1:34582` Overlay WebSocket 保持本机专用，不向局域网开放。

手机请求经过认证与账号边界检查，再由专门的查询层调用已有数据库服务或参数化 SQL，转换成有限字段的 JSON DTO。手机不能指定数据库文件、账号表前缀、SQL 或任意文件路径。查询使用当前登录账号的已验证用户 ID 构造表前缀，只开放明确列出的接口，列表均有服务端页大小上限与稳定分页游标。

初始接口集合：

| 资源                                | 读取内容                                                | 数据来源                         |
| ----------------------------------- | ------------------------------------------------------- | -------------------------------- |
| `GET /v1/status`                    | 电脑名称、接口版本、当前账号 ID、同步状态               | 运行状态                         |
| `GET /v1/friends`                   | 当前账号的好友 ID、昵称和本机已有的显示信息；搜索与分页 | 当前好友缓存及账号表             |
| `GET /v1/friends/{id}/world-visits` | 已观察到的地图访问与进出区间、次数                      | 现有好友访问地图查询             |
| `GET /v1/friends/{id}/encounters`   | 符合条件的共同好友见面次数与明细                        | `${prefix}_mutual_encounters_v1` |
| `GET /v1/friends/{id}/bio-history`  | 简介旧值、新值和观察时间                                | `${prefix}_feed_bio`             |
| `GET /v1/me/game-log`               | 可证明属于当前账号的本人游戏日志                        | 账号标记后的游戏会话             |

目前 `gamelog_*` 是全局表，没有账号键。为避免泄露其他登录账号的日志，首版给新采集的游戏会话写入账号归属标记；旧日志只有在可可靠归属时展示，无法归属的历史记录不显示，并在手机端说明原因。好友列表从已有本地记录构建，不以手机请求触发全量 VRChat 抓取。

## 配对与连接安全

首次连接时，用户在电脑端开启服务并生成短时有效、单次使用的配对二维码。二维码包含局域网地址、服务公钥指纹和一次性配对信息；安卓端扫码后校验证书指纹，电脑端再次显示设备名称并要求用户确认。确认后为该设备签发随机凭据，手机安全存储；电脑端只保存凭据的不可逆校验值和设备元数据。配对请求限速，失败不返回账号数据。

服务使用 TLS 保护局域网流量，Android 客户端固定配对时确认的公钥指纹。包括 `/v1/status` 在内的每个数据请求都要认证；只有配对握手可在尚未认证时访问，且不返回账号资料。电脑端可查看并撤销单个设备；关闭功能或切换账号时令当前会话失效。凭据不写入日志、二维码截图说明或 Git。服务不自动打开公网端口，不依赖路由器端口映射。Windows 防火墙只允许用户启用时在专用网络上访问服务。

局域网设备发现可以后续加入；首版以扫码得到地址为准。电脑 IP 变化后允许重新扫码更新地址，但必须匹配原设备的服务指纹，无法匹配就要求重新配对。

## 安卓界面

1. 首次打开显示扫码配对。连接后首页显示电脑名称、当前账号、最后成功读取时间和连接状态。
2. 「好友」页按昵称搜索，进入好友详情后用三个栏目查看地图访问、共同好友见面和简介历史。列表只呈现本机确有的记录，不把零记录解释成好友没有活动。
3. 「我的日志」展示可归属当前账号的记录；无法归属的旧日志不混入。所有长列表按页加载，详情中的时间标签说明数据是本机观察结果。
4. 电脑离线、不同 Wi-Fi、账号切换、凭据被撤销或接口版本不兼容时显示各自的可操作提示。手机不在后台持续轮询，也不缓存完整历史；页面刷新才读取最新数据。

## 错误处理与验证

接口统一返回版本化 JSON。认证失败返回 401，设备撤销返回 403，账号切换或服务关闭时连接失效，参数错误返回 400，数据缺失返回空列表而非伪造记录，数据库暂不可读返回可重试错误。客户端限制超时和重试次数，不在失败时展示过期数据为「当前」。

验收场景：

- 同一 Wi-Fi 扫码并经电脑确认后，手机能看到当前账号的好友和三类已有历史；关掉电脑端功能后立即无法再读取。
- 手机发起未认证请求、使用撤销后的凭据，或尝试查询任意账号/表/文件，都取不到数据。
- 电脑切换 VRChat 账号后，旧配对会话不能读取新账号数据；重新确认后只看到新账号的记录。
- 好友改名仍按稳定用户 ID 找到旧记录；100 条以上历史分页无重复、无遗漏。
- 历史游戏日志无法确认所属账号时不展示；新采集的账号标记日志可查看。
- 服务只监听配置的局域网接口和端口，现有 Overlay WebSocket 仍只绑定 `127.0.0.1`。
- Windows 端查询与授权逻辑有自动测试，Android 端有接口解析、认证状态和分页测试；在真实电脑与手机同一 Wi-Fi 下验证扫码、撤销、断线和重连。

## 已知限制

本功能依赖电脑保持 VRCX 运行和网络可达。好友访问与简介变化只能反映 VRCX 实际观察或保存到的记录。首次版本不迁移旧全局游戏日志到特定账号，也不提供公网连接或离线同步。
